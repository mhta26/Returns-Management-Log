# تطبيق إدارة المرتجعات للكمبيوتر

تطبيق Windows ‏10/11 **64 بت** بواجهة عربية من اليمين لليسار، وخادم مركزي للأجهزة المشتركة. يعمل دون Excel أو وحدات VBA، ودون اشتراك سحابي. تبقى المصنفات الأصلية في المستودع كما هي.

[حزم التثبيت والتنزيل](https://github.com/mhta26/Returns-Management-Log/releases/tag/desktop-v1.0.0) · [دليل التشغيل والشبكة والنسخ الاحتياطي](OPERATIONS.md)

## الوظائف

- حساب مستقل لكل مستخدم؛ الحساب الأول **مطيع** بصلاحية مسؤول. اسم المستخدم المسجّل دخوله يُحفظ ويُطبع بوصفه **أمين الصندوق**، ويثبته الخادم لمنع تغييره من نموذج السند. يُنشئ المسؤول الحسابات التالية بأسمائها وصلاحياتها.
- إضافة عملاء وأصناف وسائقين جدد، والبحث العربي بالاسم أو الكود؛ يحافظ التطبيق على الأكواد النصية والأصفار في البداية ويمنع تكرارها. تعديل السجلات الموجودة وإعدادات التصنيف وإدارة الحسابات للمسؤول.
- قاعدة البيانات الأولية مأخوذة من **آخر نسخة حالية في المستودع Returns_Management_PDF_Archive.xlsm**: ‏2701 عميل، و303 أصناف، و4 سائقين. لم تُدمج نسخ قديمة مختلفة التصميم.
- سند يحتوي العميل والمندوب والقطاع والسائق ورقم الإرجاع وتاريخ الفاتورة والكميات كرتون/علبة/حبة وتاريخ انتهاء كل صنف وسبب الإرجاع والملاحظات، مع أمين المستودع والمحاسب وأمين الصندوق.
- حالة الصنف بالألوان حسب **تاريخ الانتهاء − تاريخ السند**، والتواريخ المستقبلية مسموحة. الإعدادات المستوردة الحالية: حتى 45 يومًا «منتهي»، حتى 90 «قريب الصلاحية»، حتى 180 «مستودع التوالف»، وأكثر من 180 «صالح». الحدود والمسميات والأسباب قابلة للتعديل؛ لا نُعيد ضبطها إلى قيم نسخة أقدم.
- طباعة: تحديد عدد النسخ ثم الطابعة المحلية. يُعتمد السند وPDF في الخادم أولًا، ثم تفرغ المدخلات ويُرسل العدد المطلوب للطابعة. إذا فشلت الطباعة يبقى السند في الأرشيف ويمكن إعادة طباعته دون رقم جديد.
- PDF عربي بألوان الحالة والشعار على A4 أفقي، 22 صنفًا في الصفحة، مع تكرار العنوان والحقول السفلية عند تعدد الصفحات. تضاف صفحات تفاصيل عند وجود نصوص أطول من الخلايا لضمان عدم إسقاط البيانات. تظهر حقول السائق وأمين المستودع والمحاسب وأمين الصندوق.
- أرشيف مشترك يتضمن جميع تفاصيل السند وPDF نفسه داخل قاعدة البيانات، مع البحث والتصفية بالتاريخ والمعاينة وإعادة الطباعة وتنزيل PDF وتصدير CSV. تعديل أسماء القواعد أو حدود التصنيف لا يغير السندات التاريخية.
- ترقيم مركزي داخل معاملة واحدة مع حفظ PDF؛ الطلبات المتزامنة لا تتكرر، وإعادة محاولة الحفظ بالمعرّف نفسه لا تنشئ سندًا ثانيًا. عند فشل توليد PDF تتراجع المعاملة كلها ولا يُستهلك الرقم.
- مسودة محلية لكل مستخدم وخادم؛ لا تُحذف عند فشل الاتصال. إذا لم تتأكد نتيجة الحفظ يُقفل تحرير المسودة مؤقتًا وتتاح إعادة المحاولة بالمعرّف نفسه لمنع تكرار السند.
- استيراد XLSX/XLSM من شاشة الإعدادات مع نسخة احتياطية تلقائية قبل الاستيراد. لا يُشغّل VBA. يستورد القواعد والإعدادات وسجلات Archive وأصناف أوراق RET_ إن وُجدت. سجلات الأرشيف التي لا تحتوي أصنافًا أو PDF تبقى موسومة كمستوردة دون اختلاق تفاصيل؛ يمكن إرفاق PDF الأصلي لها.
- تنزيل نسخة احتياطية مركزية كاملة، تشمل المستخدمين والبيانات والسندات وPDF وسجل العمليات، واستعادتها عند تشغيل الخادم في مجلد جديد.

## تشغيل النسخة الجاهزة

1. ثبّت حزمة Windows على جهاز الخادم والأجهزة الأخرى. لا يلزم تثبيت Python أو Excel للحزمة المجمعة.
2. على جهاز الخادم افتح **Start Shared Server** واترك نافذته تعمل. تُحفظ بياناته في `Documents\ReturnsManagerServer`.
3. افتح ملف `connection-keys.json` في مجلد الخادم محليًا؛ الحساب الأول `مطيع` وكلمة مروره هي قيمة `initial_password`. لا تُرسل هذا الملف للأجهزة الأخرى؛ أعط كل موظف حسابه الخاص.
4. افتح **Returns Manager**. استخدم على جهاز الخادم `http://127.0.0.1:8765`، وعلى بقية الأجهزة `http://عنوان-IP-الخادم:8765`، ثم اسم المستخدم وكلمة مروره.
5. أنشئ المستخدمين من شاشة **المستخدمون وأمناء الصندوق**، وأضف البيانات الجديدة من صفحات العملاء والأصناف والسائقين. استورد مصنفك الحالي إذا لديك بيانات أحدث من النسخة المضمّنة.

إعداد مشاركة الشبكة، وتشغيل الخادم تلقائيًا، والاستعادة مذكورة في [OPERATIONS.md](OPERATIONS.md). لا تحتاج الأجهزة مشاركة مجلد SQLite أو فتح المصنف؛ الاتصال بالخادم فقط.

## التشغيل من المصدر

```powershell
cd desktop
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python launch_server.py
# في نافذة ثانية:
.venv\Scripts\python launch_client.py
```

لبناء EXE ونسخة تثبيت من Windows:

```powershell
.venv\Scripts\python -m pip install pyinstaller==6.13.0
.\packaging\build_windows.ps1
```

المخرجات داخل `release/`. يتولى GitHub Actions أيضًا الاختبارات وبناء EXE على Windows، واختبار تشغيل الحزمتين المجمعتين ونشرهما في Releases. يجب انتهاء التشغيل بنجاح قبل اعتبار رابط التنزيل متاحًا.

## حدود النسخة

الخادم واحد داخل الشبكة ويجب أن يبقى يعمل. لا تُعتمد سندات جديدة دون الاتصال؛ تبقى المسودات محلية لحين عودته. النظام متعدد الأجهزة، لكنه لا يزامن قواعد مستقلة خارج الشبكة. لا يتضمن ربطًا ضريبيًا أو ماليًا غير موجود في المصنف. ترسل حالة الطباعة «أُرسل للطابعة» عند قبول عملية الإرسال، ولا تدّعي أن الورق خرج فعليًا من الطابعة. ترخيص Windows وتوصيل الطابعات وإعداد السماح بالمنفذ تُنفذ على الأجهزة الفعلية.
